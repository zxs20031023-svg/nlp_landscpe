# 产品分析与产品文档

## 1. 产品定义

产品名称：景观设计需求转译与场地分析工作流

一句话定义：一个把“规范知识、场地信息、设计需求和参考案例”串联起来的景观设计前期智能工作台。

## 2. 产品价值

当前产品已经不只是一个“调用大模型生成 JSON”的原型，而是逐步具备了以下价值：

- 帮助用户快速形成结构化任务书
- 提升场地前期分析效率
- 用规范知识库提供一定依据支撑
- 用案例推荐降低从分析到方案启发的跳跃成本
- 把结果沉淀为可复用的项目资产

## 3. 当前版本亮点

### 3.1 功能层面

- 规范知识库构建链路完整
- 场地分析和任务书生成已经形成闭环
- 增加了本地案例推荐
- 增加了在线案例检索与案例库入库
- 已选案例可同步写入任务书成果文件

### 3.2 体验层面

- 界面从原型堆叠改成了更稳定的原生工作台布局
- 修复了 HTML 代码片段直接显示的问题
- 修复了顶部导航遮挡问题
- 增加了结果归档位置展示，减少“生成后不知道文件在哪”的问题

### 3.3 资产层面

- 任务书固定归档
- 历史记录保留
- 案例库可持续积累

## 4. 当前不足分析

### 4.1 案例质量控制仍偏弱

在线案例检索已经能用，但目前还是“搜索结果级”的能力。系统能帮用户搜到链接并导入案例库，但还不能自动抽取正文、识别项目类型、清洗噪声和生成高质量摘要。

### 4.2 结果差异化仍不足

不同角色输入虽然可以生成结果，但从最近实测看，输出仍有较强收敛性，说明系统对用户画像、使用诉求和角色差异的敏感度还需要继续增强。

### 4.3 任务书仍以 JSON 为主

当前适合研究、演示和数据对接，但若面向正式汇报或项目交付，还需要进一步补充图文报告、Word/PDF 模板和更强的版式表达。

### 4.4 后台治理能力不足

当前案例库、知识库、历史记录仍以本地文件为主，虽然适合原型和课程展示，但如果未来面向多人协作或持续运营，还需要后台管理、审核和权限机制。

### 4.5 首次使用仍依赖模型配置

系统已经比早期版本更友好，但首次使用仍要求用户理解 API Key、Base URL、主模型和嵌入模型，这对于非技术用户来说仍有门槛。

## 5. 产品优先级判断

### P0

- 保证知识库、场地分析、任务书链路稳定
- 保证案例推荐和任务书归档可用
- 保证界面展示稳定无明显错乱

### P1

- 在线案例正文抓取和自动摘要
- 案例标签化、筛选和人工编辑
- 任务书导出为 Markdown / Word / PDF

### P2

- 多项目空间管理
- 多方案对比
- 多人协作与审核
- 后台治理能力

## 6. 下一阶段产品方案

### 6.1 方向一：把在线案例做深

- 从“搜到链接”升级为“抓正文、提摘要、提标签、提亮点”
- 提供案例质量评分
- 支持案例去重和人工修订

### 6.2 方向二：把任务书做成正式成果

- 输出图文化报告
- 增加专业版导出模板
- 形成汇报友好的成果页

### 6.3 方向三：把角色差异做强

- 针对儿童家长、老人、青少年、上班族等角色建立画像模板
- 在提示词和规则层面加强差异化引导
- 提高不同用户口吻下的输出分辨率

### 6.4 方向四：把项目资产化做实

- 明确项目空间
- 明确案例资产池
- 明确知识库版本
- 明确成果版本与复用路径

## 7. 产品结论

从产品经理视角看，这个项目已经从“AI 演示型工具”迈向“有工作流逻辑的专业原型”。它最值得肯定的地方，是已经开始把知识库、规则、案例和成果沉淀串成一条连续路径。

当前最需要继续加强的，不是再堆一个新功能，而是把这三件事做深：

- 让案例能力更可靠
- 让结果表达更专业
- 让不同用户角色得到更有区分度的输出
